# Write a feature proposal

Read the existing spec, architecture and tracker. Inspect code and evidence to separate current behaviour from plans. Ask only for missing consequential choices; clear intent needs no interview.

Write a note marked *proposed* under the project's plans folder, linked from an existing topic. Leave the baseline spec unchanged unless a baseline change is authorised (then update version, traceability, decision record and regression tests together).

Include: problem, release, requirement IDs, user-visible behaviour, roles and scope, authority/data/money boundaries, acceptance checks, dependencies, out-of-scope work and unresolved owner decisions. Do not propose a new stack as a routine choice. Tests follow the project policy; do not ask whether changed behaviour needs tests. Publishing or creating issues needs explicit authority.
